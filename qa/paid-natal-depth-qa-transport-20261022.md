# v1.11 준비 — 실제 유료 요청 경로를 활용한 QA 전용 원국 심화 문단

## 기존 문제 및 이번 구현
오프라인 고정 표본 99건에서 31건이 검토 원고를 갖고 있었지만 정상 결제 고객용 첫 챕터의 실제 모델 요청에서는 네 기둥 종합 출처를 인용할 수 없었다. 이번에는 기존 사주 핵심 첫 챕터의 temperament, strength 소유권을 보존하고, **QA에서만 별도의 natal_depth 주제를 추가할 수 있는 검증 경로**를 구현했다.

## 구성
- report-core-paid-natal-depth-preview.js: 기존 검토 원고와 정확한 출생 시각·연/월/일/시의 계산 출처가 존재하는 경우에만 QA용 프롬프트를 구성. 출생 시각 미상이나 미지원 원고 차단.
- report-wire.js: QA 표시가 있을 때만 JSON strict response schema에 nullable natal_depth 문단 추가, 전송 후 응답 복원 시에도 이 문단을 별도 유지.
- report-generation-request.js: natal_depth의 허용 출처를 기존 strength와 분리. 원국 지지 관계표는 QA에서만 제한적으로 제공. 기존 월간/월지 본기 인용 범위 불변.
- report-instruction-audit.js: 실제 유료 모델 요청 직전 natal_depth의 출처와 브리프가 왜조되지 않았는지 별도 검증.
- report-core-paid-natal-depth-preview-tests.js 및 npm test: 99개 표본, 출생시간 변경·미상, 기본 요청과 QA 요청의 차이, strict schema의 출처 목록, 인위적 훼손, 네트워크 호출 직전 차단, 가상 응답 복원까지 점검.

## 오프라인 검증 결과
- 99건 고정 표본에서 검토 가능한 QA 문단 **31건**. 수작업 네 기둥 원고 기반 **4건**, 자동 근거 조합 기반 **27건**.
- 기본 유료 첫 챕터는 99건 모두 기존 월 중심 요청을 그대로 유지. 독립 심화 문단을 실제 유료 고객에게 자동 활성화하지 않음.
- 68건 미지원·출생시간 미상에서 QA 심화 요청을 강제로 생성하지 않음.
- 나머지 11개 유료 챕터 및 현행 provider request, 계산 엔진, 운영 브랜치 변경 없음.
- 가짜/교란 출처로 유료 심화 문단을 보내려 할 때 검증에서 차단. 유료 AI 네트워크 호출 0회.

## 아직 미완료
엄격한 API 계약·요청 일치와 문단 복원이 검증됐다는 뜻이지, 유료 문장 품질이 검증됐다는 의미는 아니다. 실제 모델 응답을 사람의 눈으로 평가하거나 명리 전문가가 전통 해석을 감수하지 않았다. 기존 27개 자동 문단은 machine-composed-review-only이고 기존 4개 수작업 문단도 사람의 전문 감수/고객 결제용 승인을 받지 않았다.

출시 승인 전 추가 절차: QA 전용 심화 원고에 한해 실제 AI 모델의 결과를 별도 선택 시험하고, 신강약·사령의 미검증 결론 및 분야별 중복 해석을 검사한 다음, 전문가 감수와 유료 전 보고서 회귀 테스트를 거쳐 명시적 출시 승인을 받아야 한다. **releaseVerdict: not-approved**.
