# 실제 유료 첫 챕터와 오프라인 종합 해석 연결 실사 (2026-10-22)

## 왜 점검했나
지난 단계에서 report-core-knowledge-engine.js에 99개 개발용 고정 달력 명식을 검증하고 오프라인 해석 원고를 누적했다. 실제 구매자 보고서는 별도의 report-server-contract → report-generation-request.compile → 유료 AI strict schema 경로로 작성한다. 둘을 비교하지 않고 오프라인 개발 결과가 고객의 실제 유료 해석에 반영됐다고 말할 수 없으므로, 실제 외부 AI 전송에 쓰이는 task 및 인용 source 범위를 대조했다.

## 99개 고정 명식 감사 결과 — 유료 API 호출 0
- 유료 첫 챕터에서 월간·월지 대표 지장간·계절 출처 유효: 99/99건.
- 연간·일간·시간·통근 등을 묶어 4기둥 전체를 인용할 수 있는 유료 첫 챕터 요청: 0/99건.
- 오프라인 첫 챕터 초안: 31/99건. 그중 수작업 네 기둥 종합 원고 적용 4건, 자동 근거 연결 단락 27건.
- 종합 원고를 유료 첫 챕터의 모델 요청으로 전달한 사례: 0/31건.
- 서로 다른 전체 원국인데 출생월 십성 쌍에 의한 고정 핵심 판단 문장이 재사용된 추가 사례: 45건. 이런 복수 원국 집합은 27개. 같은 월 구조의 같은 핵심 판단 자체가 항상 오류는 아니지만, 개별 원국 심화가 구현됐다는 증거는 아니다.

## 발견한 원인
실제 유료 첫 챕터의 출처 소유권은 의도적으로 월간·월지 본기/계절 중심으로 제한돼 있다. 반대로 최신 오프라인 개발은 일간·연간·시간·통근·지지 관계까지 다른 모듈에서 분석한다. 즉 오프라인 원고 개선만 반복해서는 실제 유료 고객이 받는 첫 장의 품질 개선으로 이어지지 않는다.

## 구현한 재발 방지
- report-core-paid-depth-gap-audit.js: 실제 지불 경로의 출처와 모델 요청 내용으로 차이를 정량 검증. 전달 여부를 상수로 선언하지 않고 출처·주제 자료로 판정한다.
- report-core-paid-depth-gap-audit-tests.js: 99건 및 출생시간 미상·동일 출생월 다른 시간의 실제 요청 형태를 자동 비교.
- npm test에 편입하며, 실제 문장의 유료 사용 품질과 계산/요청의 정합성은 별개의 것으로 분리한다.

## 다음 구현의 안전한 순서
1. 현행 월간·월지 본기 근거와 topic별 strict 인용 소유권을 유지한다. 인용 불가능한 4기둥 결론을 제공자에게 지시하지 않는다.
2. 추가 종합 풀이가 필요하다면 별도 심화 topic 및 독립 인용 source를 정의하고 provider 요청·strict schema·preflight·응답 후 감사를 한 변경으로 묶어 테스트한다.
3. 같은 달이지만 완전 원국이 다른 여러 실제 명식, 출생시간 변경, 미상 시간의 변형 검증을 무료 mock으로 통과한다.
4. 실제 문단/12장 보고서의 편집·전문 명리 검수를 통과하기 전 유료 출시를 승인하지 않는다.

## 상태
QA 판정은 blocked-unreviewed-paid-depth. 이는 GitHub CI가 실패했다는 의미가 아니라 유료 파이프라인에 아직 검증된 4기둥 심화 근거와 품질 검증이 미반영이라는 뜻이다. 운영 앱, 유료 AI의 호출 경로, 기존 유료 생성 파이프라인을 이번 점검에서 수정하지 않았다.
