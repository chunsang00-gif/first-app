# 작업20 — adaptive-v1 비용과 최소 유료 검증 절차 (2026-11-16)

**상태: 무료 계산 완료 / 유료 호출 미승인 / 판매·운영 배포 금지.**

## 대상과 직접 확인된 숫자

검증 대상은 **현재 실제 생성기**다. 지난 작업19의 수작업 오프라인 6장 축약본이 생성기에 적용됐다는 뜻이 **아니다**.

- 고정 합성 입력: 음력 1982-11-24, 14:20, 남성, ISFP, 2027년 분석.
- 실제 가변형 장 선택: **9장** (사주 기본, 사주×MBTI, 결정, 금전, 직업, 관계, 스트레스, 종합, 2027년).
- 자동으로 제외: 2027년 금전·직업·관계 세 장(현재 입력의 직접 근거 부족).
- 생성 계획: **본문 6회 + 종합 1회 = 총 7회**, 그보다 많은 유료 호출 금지.
- 기존 GPT-4.1 출력 토큰 한도: 첫 장 18,000, 나머지 본문 각 12,000×5, 종합 12,000; **총 90,000 출력 토큰이라는 요청량 상한**. 실제 출력 목표가 아님.
- 정확한 실제 **첫 장 요청봉투 직렬화 크기**: **68,141 UTF-8바이트**. 모델 input_tokens로 직접 측정한 값은 아님.
- 이후 5개 본문봉투는 이전에 생성된 실제 문단이 없는 **미래 호출 추정 구성**. 정확한 다음 호출의 해시·토큰 수가 아님.

출처: `node report-adaptive-v1-offline-cost-plan.js`, GitHub CI 실행 결과; 프로젝트 코드 `report-paid-batch-plan.js`, `report-chapter-selection.js`, `server.js`.

## 가격과 계산 (2026-11-16 공개 요금)

현재 코드가 사용하는 GPT-4.1의 공개 요금은 **입력 $2 / 100만 토큰, 출력 $8 / 100만 토큰**, 캐시 적용 시 입력은 별도 요금이다. [공식 GPT-4.1 모델](https://developers.openai.com/api/docs/models/gpt-4.1). 현재 모델은 **Deprecated**이고 공지된 종료 예정일은 **2027-01-14**다. [OpenAI deprecations](https://developers.openai.com/api/docs/deprecations).

공식 요금으로 계산하되, 실제 토큰 사용량이 없는 구간은 다음처럼 **가정한 비용 시나리오**다.

| 요청 | 장 | JSON 요청 크기(바이트) | 요청 출력 제한 | 예시 비용(USD) |
| --- | --- | ---: | ---: | ---: |
| 본문1 | 사주 기본 | 68,141 | 18,000 | 0.284378 |
| 본문2 | 사주×MBTI | 87,107 | 12,000 | 0.298310 |
| 본문3 | 결정·스트레스 | 99,739 | 12,000 | 0.347574 |
| 본문4 | 금전·직업 | 161,140 | 12,000 | 0.494376 |
| 본문5 | 관계·종합 | 113,780 | 12,000 | 0.423656 |
| 본문6 | 2027년 | 62,420 | 12,000 | 0.344936 |
| 종합 | 실제 원고 완성 후 구성 | **미작성** | 12,000 | 0.196000* |

*종합은 **입력 50,000토큰을 가정**했고 출력은 12,000토큰을 전부 쓰는 극단적 계획값을 넣었다. 아직 실제 종합용 봉투를 생성한 것이 아니다.

**합계 계획값: 약 US$2.38923**. 이 시나리오의 가상 입력 합계는 **834,615 계획 토큰**이며, 7회 요청의 전체 출력 한도 90,000토큰을 전부 사용한다고 가정한다. 본문 요청 입력값은 **요청 UTF-8 바이트 + 2,048 + (앞선 본문 수 × 12,000) 토큰의 별도 여유치**로 계산한다. 실제 토크나이저를 사용한 값이 아니며 실제 이전 원고를 담은 요청과 다르다. **$2.38923은 보장되는 청구 상한이 아니라 예산 계획 시나리오다.**

출력 한도만으로 계산되는 부분은 **$0.72**(90,000 × $8/100만). 입력 부분은 과금 시점의 실제 입력 토큰과 이월 원고 길이에 따라 변한다. 사용량·모델 접근권·API 정상 수용·환율·세금은 여기서 확정되지 않는다. 성공한 실제 API 응답의 `usage.input_tokens`·`usage.output_tokens`를 **비공개 수집해야 확정 청구 추정**이 가능하다. 개발 브랜치의 첫 장 전용 QA는 응답 콜백의 실제 `usage`를 비공개 첫 장 보관 파일에 기록하도록 보완했으며, 무료 가짜 응답으로 메타데이터 전달을 검증했다. 아직 실제 유료 응답의 사용량은 수집하지 않았고, **후속 본문 5회+종합 1회 전체의 비용 영수증 보관은 별도 검증 대상**이다.

## 최소 실행 순서 — 지금은 승인 전이라 0단계까지만

0. **무료 검증:** 해당 개발 브랜치의 SHA와 원고 버전을 고정하고 `npm test`, `npm run smoke`, `node report-adaptive-v1-offline-cost-plan.js`를 실행한다. 소비된 과거 결제 승인값 재사용 금지. 현재 비용 계획은 해당 SHA에 종속된다.
1. **별도 사전 승인 필요:** 정확한 요청 SHA, 모델, 첫 장 요청의 출력 제한(18,000), 실제 비용 기록 방법, **1회 제한**을 명시해 사용자의 새로운 명시적 승인을 받는다. 모델을 바꾸면 새 SHA·비용·스키마 검증을 다시 해야 한다. 승인 없이 유료 호출 금지.
2. **첫 장 1회만 검증:** 개발용 비공개 실행기에서 합성 입력으로 첫 장만 생성·보관한다. 잘못된 JSON/계산·출처·독자 가치 결함은 **즉시 중단**, 자동 재시도·남은 6회 진행 금지. 실제 원문과 사용량 정보는 비공개 보관; 공개 로그에 고객 내용 금지. 기존 2026-11-07 유료 실패 승인·워크플로 재사용 금지.
3. **결제 가치에 대한 사람의 완독:** 먼저 첫 장을 무료 풀이와 나란히 읽고 정보 차이, 계산 출처, 두 의미의 연결, 단순 용어 강의·반복 여부를 구체적 문장 단위로 평가한다. 모호하거나 반복되면 **HOLD**. 이 평가가 1회를 추가 생성하라는 허가가 아니다.
4. **첫 장 통과 후 별도 승인:** 검증된 첫 장을 다시 과금해 생성하지 않고 기존 비공개 체크포인트를 사용하는 것이 안전하다. 다만 체크포인트 재개·최대 호출 수·후속 실비 기록이 검증된 뒤에만 남은 **본문 5회 + 최종 1회**를 별도 승인 하에 실행한다. 중간 실패는 즉시 중단한다.
5. **전체 완독 및 출시 판단:** 실제 전 장의 서로 다른 독립 해석, 반복 여부, 유료 가치, 출처 정확성, 개인사·미래 창작 여부, 전문가 검토를 확인한다. 결제·저장·환불/고객 전달 안전성은 운영 배포 전에 별도 검증한다. 최종 승인 없이는 판매·운영 배포 절대 불가.

## 남은 명확한 차단 조건

- **현재 실제 AI가 생성한 전체 보고서 1건이 없다.** 6장 오프라인 수동 원고와 실제 생성 결과를 혼동하면 안 된다.
- 첫 실유료 원고는 독립적 독자 가치 부족으로 2026-11-08 **HOLD**였다. 자동 테스트 통과로 덮지 않는다.
- **첫 장 실유료 토큰 계측은 구현만 완료, 실제 과금 기록은 없음.** 후속 본문과 최종 종합의 사용량 비공개 기록 및 총비용 합산은 정식 유료 실행 전 반드시 점검해야 한다. 현재 가격은 공개 표준 가격이며 실제 공급자 접근 여부는 검증하지 않았다.
- 모델이 Deprecated 상태이므로 출시 모델을 정하기 전 호환성과 장기 운영을 다시 검토해야 한다.
- **출시 판정 HOLD**, 별도 유료 호출 승인 **없음**, 신규 유료 요청 **0회**, 운영 브랜치 **변경 없음**.
