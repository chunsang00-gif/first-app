# 기존 앱 첫 챕터 — 월간·월지 본기 관계의 5방향 체계화

## 목적과 본질
기존 v0.8에서 99건 전부 편집 개요는 만들어졌지만, 개요의 가장 중요한 두 출처를 연결하는 **오행 생·극의 방향**이 단락에서 빠져 있거나 두 가지 방향이 반대로 기술될 위험이 있었다.
이에 12개 월지 × 일간 10종의 실제 계산값을 조합하는 방식을 사용하되, 검증된 **출생월 겉글자와 안쪽 대표 글자**의 관계만 좁게 다룬다.

## 동작
- `report-core-month-bridge.js`는 `seasonal.relation(월지 본기 오행, 월간 오행)`으로 5가지 분기를 독립 재계산한다.
- 같은 오행, 본기가 월간을 생함, 월간이 본기를 생함, 본기가 월간을 극함, 월간이 본기를 극함을 **다른 관계**로 유지한다.
- 십성이 같다는 사실과 오행이 같다는 사실을 혼동하지 않고, 전통적 생·극 관계를 실제 도움·사건·기질 강약으로 확정하지 않는다.
- 해당 월·글자·십성·계절·자료 출처가 사주 계산과 다르면 편집 개요도 만들지 않는다.
- 기존 99건의 `editorialOutline` 안에 `monthBridge`를 포함하되, 출시 미승인/독자용 글 아님/유료 생성 경로 미연결 상태를 그대로 지킨다.

## 목표가 아닌 것
자동 생성한 일반 문장을 유료 사주풀이로 간주하지 않는다. 계산 관계표를 나열한 작업 메모가 곧 전문가 해석의 깊이는 아니다. 해당 방향이 **성격이나 돈·직업·관계가 좋고 나빠질 원인**이 된다는 주장도 하지 않는다.

## 검사
99건 고정 달력 입력에서 5가지 방향이 모두 나오는지, 각 경우 겉·안쪽의 원천ID·십성·방향이 동일한지, 오염된 방향·계절·십성 데이터를 거부하는지, 시각 미상 및 MBTI·대상 연도 수정에도 출생월 관계가 불변인지를 확인한다.
직접 생성한 유료 API 호출은 0회이고 운영 배포나 기존 계산/유료 AI 요청은 변경하지 않는다.
