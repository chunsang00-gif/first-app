## 비교 범위 (새 과금·배포 없음)

- **유료 실제 생성 원문:** 2026-10-19 Actions `39179958854`에서 생성 후 개인 파일로 보존된 첫 장. 실제 본문을 직접 읽고 판단했지만 **원문 문장·개인 식별정보를 공개 저장소에 복사하지 않는다.**
- **동일한 검증 명식의 연구용 개정안:** `report-core-paid-exact-winter-revised-chapter.js` 및 `report-core-paid-exact-winter-revised-chapter-tests.js`. 이 코드는 음력 1982-11-24, 14:20, 남성, ISFP, 2027년의 고정 시험 입력에만 해당한다.
- **다른 명식의 최신 실험:** `report-core-v2-source-bound-manuscript.js`의 1994년 계산 사례는 서로 다른 자료다. 이 수정 결과를 1982년 유료 원문이 개선됐다는 근거로 사용하지 않는다.
- `saju-mbti-app` 운영 브랜치, 실제 유료 보고서 생성 요청, API 과금, 결제 기능을 변경하지 않는다.

## 실제 원문의 불합격 이유 — 직접 판독

1. 첫 장의 중심 판단은 *새 정보를 자기 방식으로 이해하고 필요한 자원을 활용한다*는 뜻이다. 이는 서로 다른 사람에게 그대로 사용할 수 있을 정도로 넓은 결론이다.
2. 첫 문단은 주변 도움의 가능성·조건과 그 한계를 오래 설명한다. 출생정보로 확인한 것과 현실에서 실현될 도움을 분리한 점은 적절하지만, 구매자가 얻는 구체적 사주 해석이 부족하다.
3. 둘째 문단은 정보 이해와 자원 확보를 다시 반복하고, 정보와 자원을 모두 살피라는 일반 조언으로 마무리한다. 실제 자료가 뒷받침하는 새로운 조건부 판단보다는 두 전통 분류의 뜻을 나열하는 데 가깝다.
4. 문장 안의 가정과 면책은 유지할 필요가 있지만, 고객의 기질을 구별하는 주요 내용보다 앞서면 유료 가치를 보증할 수 없다.

위 사항은 실제 원문에 대한 편집 판정이다. 자동 점수·문자열 유사도만으로 결론을 내리지 않았다.

## 동일 명식 개정안에서 실제로 달라진 점

- 출생월의 정보 이해·자원 선택 이야기를 반복하는 대신, 특정 **날·시간·겨울 조건**에 적용되는 고전 문헌의 해석 범위와 다른 고전의 별도 조건을 구별했다.
- 같은 날짜의 14:20 vs 20:20을 비교하여, 출생시간이 다르면 일부 고전 조항의 적용 조건이 사라짐을 기록했다. 이는 **해석에 적용할 문헌 범위가 달라진 것**이지 실제 성격·삶·금전·미래가 달라질 것이라는 검증은 아니다.
- 연구용 원고는 독자의 이해를 돕는 글이라기보다 고전의 조건·계산 차이를 설명하는 글에 가깝다. 고전 두 문헌 간에 어떤 원리가 우선하는지도 승인되지 않았다.
- 결과적으로 **출처의 구체성은 개선됐지만 소비자가 추가 비용을 지불할 개인별 사주 해석 가치는 아직 증명되지 않았다.**

## 근본 문제와 다음 작업의 완료 조건

**근본 문제:** 사실 출처가 늘어도, 그 출처에서 어떤 전통 해석을 어떤 우선순위로 적용하는지에 관한 **채택된 해석 규칙**이 없으면 명식마다 다른 심화 해석 대신 계산 소개 또는 보편적 상황 조언만 늘어나기 쉽다. 이 한계를 정규식 추가·기계적 글자수 증가·반복 유료 호출로 덮지 않는다.

다음 변경은 **1982년 동일 명식의 단 하나의 조건부 심화 주장**을 대상으로 한다.

1. 적용할 고전 조항의 원문·출전과 모든 성립조건을 기록하고, 왜 해당 명식에 적용 가능한지 계산 출처와 함께 독립 검토한다.
2. 이 조항에서 실제로 따라 나오는 **전통 해석의 차이**와 따라 나오지 않는 **성격/미래 단정**을 구별한다. 상충하는 다른 문헌 조건의 해석 우선순위를 미확정이면 그대로 보류한다.
3. 동일한 날짜의 출생시간 반례에서 해당 주장이 왜 달라져야 하는지, 문장에 어떤 차이가 생기는지 설명한다.
4. 일반 독자가 보고 '무료/기본 첫 장에는 없던 무엇을 알게 됐는가'를 대답할 수 있는지, 분야/자료만 바꾼 중복과 강의체 문장 없이 독립적으로 검수한다.
5. 위 단계 전에는 `approvedForCustomer:false`, `paidWriterAuthorized:false`, 운영 비반영·추가 유료 모델 호출 금지를 유지한다. 자동 테스트 성공을 편집 승인이라고 보고하지 않는다.

**결론: EDITORIAL FAIL / RELEASE NOT APPROVED.** 근거를 더 나열하는 것만으로는 유료 보고서 완성에 가까워졌다고 평가할 수 없다.
