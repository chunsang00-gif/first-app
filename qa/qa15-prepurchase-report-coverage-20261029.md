# QA15 — 결제 전 실제 제공 범위 표시 (고객 경험 개선)

검증일: 2026-10-29. 기존 `fix-paid-qa-fact-bindings-20261014` **작업 브랜치에만** 적용. `main` / 운영 `saju-mbti-app`에 병합·배포하지 않았다.

## 변경 이유

기존 구조는 유료 목차 **12장**, 그 안의 실제 세부 항목 **28개**를 정의하고 있지만, 근거 부족 시 일부 장은 빠지고 비필수 항목은 `null`로 생략된다. 현재 정책상 이 중 6개 항목은 항상 비활성화되어 있어 35항목 고정 상품을 약속할 근거가 없다. **현재 실제 판매 보고서 생성은 결제/구매권 확인 미구현으로 403 차단**되어 있다.

따라서 비활성 항목을 무작정 켜거나 가짜 35항목을 만들지 않고, 출생정보 입력 후 **무료·무과금 제공 범위 미리보기**를 실제 앱 흐름에 연결했다.

## 실제 개발

- `report-product-coverage.js`: 사용자 입력을 서버의 `report-facts-node.build`로 다시 계산하고 `report-calculation-integrity.verify`로 검증한 뒤 **정식** `report-analysis-guidance.preflight` + `report-chapter-selection.select`를 실행한다. 실제 장 ID와 항목 ID는 `report-quality-node.IDS`, `report-outline.topics`를 그대로 사용한다. 장의 한국어 이름, 포함 여부, 제외 사유, 활성 후보 문단 상한만 출력한다. 실제 계산 표/이름/생년월일/출생지·명식 원본은 응답에 넣지 않는다.
- `server.js`: `POST /api/report-coverage`를 추가. `/api/calculate`와 동일한 `validateInput` 적용, 출생시간 미상은 기존과 같이 낮 12시 계산 보조를 이용한다. HTTP 응답은 `cache-control:no-store`이며 사용자 결제 기록, 모델 호출, 보고서 작업 생성 없이 즉시 응답한다.
- `report-api-contract.js`: 무료 범위 조회용 별도 `coverage(input)`를 추가. 기존 `generate`, `resume` 로직은 유지.
- `live-report-ui.js`: 새 사용자 흐름에서는 계산 완료 후 `/api/report-coverage`로 **제공 가능한 장·항목의 상한과 제외 이유**를 표시. 실제 유료 보고서 문단이 완성됐다고 하지 않고, 결제와 정식 생성은 준비 중이라고 밝힌다. 클릭으로 입력 화면에 돌아간다. 기존 저장/재개 경로는 유지.
- `report-product-coverage-tests.js`: 합성 4개 명식의 9장/19항목, 10장/19항목, 10장/20항목, 11장/20항목 사전 상한과 내역을 확인. 고객 이름/출생일/출생지 미반환, 사용자가 보낸 위조 chart/facts/purchaseEnabled 필드 무시, 판매 허가=false, 모델 호출 0을 검증.
- `smoke-test.js`: 실제 로컬 HTTP 서버에서 새 endpoint 200/422, 출생일 검증, 결과 no-store, 모바일 화면이 무료 범위 조회 경로를 사용함을 검사. 기존 API/결제 차단 테스트도 그대로 사용.
- `report-timing-tests.js`: 기존 분석 중 소요시간 UI 테스트를 유지하며, 새 사용자 흐름은 무료 조회 완료 후 범위 화면을 표시하고 유료 생성 호출을 시작하지 않는다고 추가 검증.
