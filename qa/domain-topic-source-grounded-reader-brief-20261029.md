# 도메인 유료 원고: 항목별 실제 근거에 맞춘 작성 질문 연결

날짜: 2026-10-29 · 작업 브랜치 `fix-paid-qa-fact-bindings-20261014` 전용.

## 실제 문제

목차에서는 금전의 벌이/지출, 직업의 일하는 방식/협업/학습, 관계의 친밀감/표현, 스트레스의 압박/대처를 분리했지만 AI에 전달되는 **실제 항목별 글쓰기 질문과 두 상황의 비교**는 기존 일반적인 '다르게 작성하라' 지침에 의존했다. 동일한 재성·식상 등 전통 분류가 여러 장에 합법적으로 포함될 때, 그 출처가 무엇을 새롭게 설명하는지 독자가 구별하기 어려웠다.

## 코드 변경

- **`report-domain-topic-reader-brief.js` 신설**: 9개 실제 활성 가능 주제 (금전 2, 직업 3, 관계 2, 스트레스 2)에 대해 각각 독립된 독자 질문, 대조할 두 개의 **명시적인 가상 상황**, 다른 장에서 반복하면 안 되는 결론을 정의한다. 명식별로 허용된 `citableFacts`에서 **정확한 출처 ID**, 해당 분류가 속하는 재성/식상/관성/인성/비겁 집단의 종류, 계산 위치 수를 확인한다. 이미 존재하는 `report-source-ledger.usedPaths()`의 실제 이전 인용 기록만 겹치는 근거로 표시하고, 사용 가능했을 뿐 인용하지 않은 출처는 사용했다고 하지 않는다.
- 분류가 2가지면 서로 다른 **전통적 질문**을 명시하고, 1가지만 있을 때는 다른 사람의 생활 성향이나 측정되지 않은 강도를 꾸며 두 질문을 만든 것처럼 쓰지 않는다. 이전 장에서 이미 인용한 출처의 문단은 새로운 독립적 해석을 만들 수 없으면 **비필수 항목 null**로 둔다. 원국 사실 자체와 해석의 결론/실제 관찰을 혼동하지 않는다.
- **`report-generation-request.js`의 실 OpenAI provider boundary**에서 본문 단계의 실제 `topic.citableFacts`에 위 구체적인 `topic.readerDistinction`을 연결한다. **출력 strict JSON의 해당 `paragraphs[topic].text.description`에도 동일한 질문과 가상 대조 상황을 명시**해 실제 작성할 문단 단위로 전달한다. `state-limits` 항목, 첫 장, 미지원 항목에는 새 필드를 넣지 않는다.
- 사주 기본 첫 장과 QA용 `natal_depth`는 과거 유료 QA 요청의 해시가 동결된 범위이다. 처음에는 모든 주제에 null 필드를 붙여 동결 요청 지문이 달라진 것이 CI에 검출되어, **해당 필드는 지원되는 활성 도메인 주제에서만 추가**하도록 교정했다. 기존 승인된 요청·모델·토큰 한도·스키마를 변경하거나 유료 호출 보호 코드를 수정하지 않았다.
- `report-domain-topic-reader-brief-tests.js`에서 4개 합성 명식의 **실제 provider compile 및 실제 strict JSON schema**를 생성하여 새 질문이 정확한 출력 문단에 연결됐는지 확인. 활동 36건, 비활성 12건, 금전 벌이/지출 다른 질문 4건, 실제 이전 인용과 단순 허용 출처의 구별 검증.
- `package.json`의 전체 무료 `npm test`에 위 검사를 추가.
