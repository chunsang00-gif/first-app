# QA8 — 다른 명식으로 첫 장 풀이가 새어 나가는 문제 검증

## 왜 이 작업을 했는가
QA7의 새로운 독자용 첫 장은 오직 합성 명식 1994-07-15 14:20, 甲戌/辛未/壬寅/丁未를 위한 연구 원고다. 같은 생일의 다른 출생시간이나 다른 사람에게 해당 고전 관계를 복사해서는 안 된다. 기존 QA3에는 이미 8개 명식의 서로 다른 원고와 실제 디코더·기계 편집 테스트가 있었다. 이번에는 이를 중복 구현하지 않고 **다른 출생정보로 원고·출처·사례를 옮겨 붙이는 일을 별도의 부정 테스트로 차단**했다.

## 신규 코드
- `report-qa8-multichart-transfer-guard.js`: 작업 브랜치의 무료 테스트 범위에서만 운영. 실제 `writer.compile(prompt)`로 산출한 첫 장의 `serverOwnedWritingContract`를 독립 함수로 재계산해서 일치 검사. 원고의 명식 지문, 계약 종류, 해/시간 위치, 지정된 근거 출처, 가상 사례 이름을 서버 원본 계약과 대조.
- `report-qa8-multichart-transfer-guard-tests.js`: 기존 8개 합성 명식을 QA3 실제 연구용 원고 생성기로 만들고, QA8에서 각각 확인. 계약 없는 명식은 문단이 null인 경우에만 `source-abstention` 반환. 다른 명식으로 복사한 원고, 조작한 refs/scene, 근거를 벗어난 글은 오류로 거절.
- 기존 QA7 고전 문장에 대해서는 `report-core-1994-dingren-classical-rule-audit.inspect()`의 **정확한 계산 입력·명식·출생시간**을 확인한다. 오후 8시 20분의 다른 시주에는 원고 재사용 불가. 다른 고전 조건이 있을 수 있다는 이유로 QA7의 해당 문장을 자동 허용하지 않는다.
- `package.json`의 전체 `npm test`에 QA8 무료 검증 등록.
