# 작업59 — 실제 Chromium 모바일 화면 렌더링, 한글 가독성, 첫 숫자 입력 접근성

**2026-11-22 (KST) / 개발 브랜치 전용 / 운영 배포·유료 AI·결제 호출 없음**

## 왜 필요한가

작업57~58의 체험판과 앱 공통 계산은 Node의 가상 DOM에서 정상 실행됐지만, **실제 브라우저가 렌더링한 화면의 글자·가로 넘침·오프라인 저장/다운로드**를 직접 검증한 적이 없었다. 가상 DOM 통과만으로 ‘휴대폰 사용성 검증 완료’라 표현하지 않기 위한 별도 검사다.

## 실제 브라우저에서 확인

`qa-work59-real-browser-mobile.js`는 실제 CI Ubuntu 러너의 **Google Chrome(Chromium 기반)**을 `playwright-core`로 띄우고 실제 오프라인 단일 파일 `workbook-mobile-offline-trial.html`을 연다. 테스트 내부에서 실제 결제·보고서 API를 호출하거나, Render 사이트로 배포하지 않는다.

| 렌더링 | 확인 |
|---|---|
| 390 × 844 모바일 | 초기 안내, 부분 입력 64시간, 합성 사례 36시간·20만원 부족, 상세 펼침, 개인 텍스트를 뺀 요약 |
| 320 × 720 작은 모바일 | 동일 입력에 실제 가로 넘침·중요 입력의 잘림이 없는지 측정 |
| 1280 × 900 데스크톱 | 똑같은 HTML의 반응형 레이아웃 확인 |
| 브라우저 실제 `Blob` 다운로드 | `learning-time-budget-summary.txt` 저장, 파일의 UTF-8 내용과 **사용자가 화면에서 확인한 요약 텍스트가 정확히 동일**한지 검증 |
| 입력 수정과 초기화 | 이전 결과의 복사·저장을 비활성화해 오래된 데이터 재사용 방지 |
| 브라우저 로그·요청 | JS 페이지 오류 없음, 외부 HTTP(S) 요청 없음 |

**최초 실제 렌더링에서 발견한 버그:** Ubuntu CI 크롬의 한글 대체 글꼴 부재로 화면 캡처의 한국어가 네모로 표시됐다. `.github/workflows/test.yml`의 전용 visual job에서 **한글 글꼴을 조건부 설치**하고, `fc-list :lang=ko` 결과가 비어 있으면 테스트를 실패 처리하도록 추가했다. 글꼴 설치 후 캡처의 한글이 실제로 읽히는 것을 확인했다. **이것은 CI 캡처 환경의 문제**였으며 사용자의 실제 휴대폰에 동일 문제가 있었다는 증거는 아니다.

**화면을 보고 발견한 사용성 장애:** 390px 세로 첫 화면에서는 주요 ‘매주 학습시간’ 입력칸이 스크롤 아래에 위치했다. `workbook-mobile-offline-trial.html`의 사용 방법 위쪽에 **‘내 숫자로 바로 시작’** 버튼을 추가하고, 클릭하면 첫 숫자 입력칸으로 스크롤하여 포커스하도록 변경했다. 실제 크롬 테스트에서 `document.activeElement`가 해당 숫자 입력칸으로 바뀌는지 확인한다. 체험판만 변경했으며 상용 사주 보고서 마법사의 입력 형식과 결제 흐름은 바꾸지 않았다.
