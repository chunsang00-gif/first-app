# 작업54 — 고객이 실제로 활용할 수 있는 선택 비교 보고서 미리보기

## 1. 새로 구현한 내용

고객이 1단계 화면에서 **현재 일을 유지할지 새 기술을 배울지** 묻고, 본인이 알고 있는 현재 일·목표 기술·학습시간·교육비를 입력하면, 기존의 단순 계산 결과에 더해 **‘두 선택에서 확인할 내용’과 ‘부족한 조건을 바꾸는 계산상 방법’**을 보여준다.

- **현재 일 유지**: 급여·근무시간·안정성·고용조건은 입력받지 않아 **숫자 비교 불가**라고 표시한다. 이를 사주·MBTI만으로 추정하지 않는다.
- **기술 학습 또는 병행**: 고객이 입력한 주당 시간, 필요 총시간, 목표기간, 교육비, 예산을 실제로 계산해 제약과 부족분을 표시한다.
- **실행 가능성 조정안**: 목표 기한을 지키기 위해 **주당 얼마의 시간을 더 확보해야 하는지**, 현재의 주당 공부시간을 유지하면 **총 몇 주가 필요하고 목표를 몇 주 늘려야 하는지**, **교육비 예산 부족분**을 각각 계산한다. 이는 서로 다른 대안이며 실제 조정이 가능한지 고객이 검토해야 한다.
- **반드시 확인할 사항**: 실제 근무표와 수업시간의 중복, 교육비 외 교통비·시험비·생활비, 현재 직장에서 학습 병행이 가능한지 등을 확인하게 한다. 근무조건은 확인되지 않았으므로 선택을 자동 추천하지 않는다.

숫자 5개 중 입력하지 않은 항목은 추측하지 않는다. 시간만 있으면 시간 조정안만, 예산만 있으면 예산 확인만 표시한다. 주당 학습시간 0시간이면 **기간만 늘리는 해결안은 만들지 않는다**. 주당 168시간이나 목표 260주를 넘는 실행안도 실제로 가능한 계획인 것처럼 제시하지 않는다.

## 2. 동일한 고민, 서로 다른 현실 데이터

아래 두 사례는 실제 고객 데이터가 아니라 **합성 입력**이다. 현재 일: 물류 재고 확인, 배울 기술: 엑셀 자동화, 필요 학습시간: 60시간, 목표: 8주.

| 구분 | A — 여유 조건 | B — 부족 조건 |
| --- | ---: | ---: |
| 주당 가능한 학습시간 | 8시간 | 3시간 |
| 목표기간에 배치할 수 있는 시간 | 64시간 | 24시간 |
| 목표기간 내 부족 학습시간 | 0시간 | **36시간** |
| 목표 유지에 필요한 주당 시간 | 7.5시간 | 7.5시간 |
| **추가로 확보할 주당 시간** | 0시간 | **4.5시간** |
| 현재 속도로 필요한 전체 기간 | 8주 | 20주 |
| **추가로 필요한 기간** | 0주 | **12주** |
| 교육비 / 사용 가능 예산 | 15만 / 20만원 | 30만 / 10만원 |
| **추가로 필요한 교육비** | 0원 | **20만원** |

B에 제시하는 조정 경로는 **① 주당 4.5시간을 추가로 확보하는 안 또는 ② 목표 기간을 12주 연장하는 안**이다. 교육비 20만원 부족은 별도로 해결해야 한다. 단순 산술값이며 이 계획을 실제로 실천할 수 있는지, 교육과정을 이수할지는 확인하지 않았다.

## 3. 수정한 실제 파일

- `report-work-skill-decision-comparison.js`: **브라우저와 Node 공통** 비교 보고서 계산, 두 선택의 정보 부재를 분리, 조정 가능한 수치를 계산
- `report-work-skill-decision-workbook-ui.js`: 기존 1단계 무료 미리보기에 카드 두 개와 조건 조정안, 후속 체크리스트 추가
- `index.html`: 새 비교 엔진을 동일 계산 라이브러리 다음에 로드
- `report-work-skill-decision-workbook.css`: 모바일에서 1열·큰 화면에서 2열 선택 비교 카드를 표시

## 4. 제품성과 기술적 상태

본 변경은 고객의 **직접 입력값에 따른 실행 조건**이 계산되는지 입증하는 범위다. **사주×MBTI 유료 보고서의 상품성이나 소비자의 지불 의사, 전통 명리 해석의 개인 미래 예측력은 입증하지 않는다.**

**판매 판단: 미승인**. 12장·35항목 구성 강행, 품질이 확인되지 않은 새 유료 원고 생성, 운영 배포 및 새 결제는 모두 범위 밖이다.

다음의 실제 상품 실험은 비과금 개발 브랜치에서 만든 결과 화면의 **사용자 가독성·질문 부재·선택 실행력** 평가로 한정하고, 실제 배포나 유료화가 필요하면 반드시 별도 승인을 받는다.
