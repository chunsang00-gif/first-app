# 작업53 — 실제 입력 화면에 무료 시간·예산 계산 미리보기 연결

작성: 2026-11-22 (KST). 개발 브랜치 `fix-paid-qa-fact-bindings-20261014`. **운영 배포, 유료 AI 호출, 고객 결제/판매 승인 없음.**

## 1. 사용자가 실제로 볼 수 있도록 만든 기능

`index.html` **STEP 01**의 기존 `readerDecision`, `currentWork`, `targetSkill` 입력 바로 아래에 **‘현재 일과 새 기술, 시간·예산 비교’(무료 미리보기)** 패널을 추가했다.

**발견 조건:** 사용자가 직접 쓴 질문이 **‘현재 일을 유지할지 새 기술을 배울지’**처럼 실제 두 선택일 때에만 계산 패널과 기존 상황 입력이 열린다. 다른 고민으로 바꾸면 기존 상황 입력/시간/비용/결과를 지우고 패널을 숨긴다. 사주나 MBTI 입력이 없어도 이 비교 계산 자체는 독립적으로 작동한다.

선택 입력하는 5개 숫자:

| UI 입력 | 단위 | 검증 한계 |
| --- | --- | --- |
| 주당 확보 가능한 학습시간 | 시간 | 0~168, 0.5시간 단위 |
| 고객이 예상한 필요 학습시간 | 시간 | 0.5~10,000, 0.5시간 단위 |
| 목표 기간 | 주 | 1~260, 정수 |
| 고객이 예상한 교육비 | 원 | 0~1억 원, 정수 |
| 사용할 수 있는 교육 예산 | 원 | 0~1억 원, 정수 |

**그 자리에서 즉시 계산**: 목표 기간 내 가능한 학습시간, 목표에 필요한 주당 학습시간, 현재 속도로 필요한 주수, 목표 기간에 부족한 시간, 교육비에 부족한 금액. 일부 입력만 있으면 **입력이 부족한 항목만 표시**한다. 예산 0원과 미입력을 구별한다. 주당 시간 0시간이면 완료 예상 주수를 임의로 만들지 않는다. 고객의 두 선택이 완전히 상호 배타적이라고 가정하지 않는다.

### 같은 고객 고민에 대한 합성 입력 예시

- A: 주 8시간, 총 60시간 필요, 8주 목표, 교육비 150,000원 / 예산 200,000원 → **총 64시간 가능, 부족 0시간·0원, 입력 기준 총 8주 소요**.
- B: 주 3시간, 총 60시간 필요, 8주 목표, 교육비 300,000원 / 예산 100,000원 → **총 24시간 가능, 36시간·200,000원 부족, 입력 기준 총 20주 소요**.

이것은 **고객이 직접 입력한 수치의 사칙연산**이지, 사주 풀이로 학습 속도, 실제 능력, 미래 수료 여부를 알아낸 결과가 아니다. 현실 교육과정별 학습 필요시간·비용이 정확한지 검증하는 서비스는 아직 없다.

## 2. 실제 구현 경로

- `report-buyer-decision-context.js`: **기존 Node 입력 검증을 브라우저와 공유**(동일 함수·동일 기준)
- `report-work-skill-decision-workbook.js`: 작업52의 **동일한 실제 계산 함수**를 브라우저와 Node에서 실행하는 공용 파일로 변경. 계산식 복제 없음
- `report-work-skill-decision-workbook-ui.js`: 실제 DOM에 있는 입력과 연결, 무료 즉시 업데이트/빠진 값 알림/주제 전환 때 값 삭제. 사용자 텍스트는 `textContent`로 표시
- `report-work-skill-decision-workbook.css`: 모바일 1열/큰 화면 2열 구성, 기본 접근성·가독성
- `index.html`: **실제 1단계 입력 위치**에서 위 스크립트와 패널 로드
- `public-files.js`: 정확한 4개 새 JS/CSS 파일만 공개 허용. 기존 `server.js`, QA 원본/민감 자료는 여전히 HTTP 접근 거부
- `qa-work-skill-decision-workbook-ui-tests.js`: 실제 브라우저 자바스크립트를 VM에서 실행해 가상 DOM의 입력·수정·주제 변경·결과 상태를 검증, **Node 서버 계산 결과와 동일한지 직접 비교**, 외부 네트워크·결제·모델 호출 여부 0을 확인
- `report-public-entry-scripts-tests.js`: 실제 서버에서 새 JS/CSS가 200으로 응답하는지 확인하고 내부 소스는 404인지를 검증

## 3. 명확한 미출시 경계

- **서버의 사주 계산 요청 `/api/calculate`이나 기존 `live-report-ui.js`의 보고서 제출 데이터에 5개 수치를 추가하지 않았다.** 오직 브라우저 안에서 계산하며 서버·외부업체로 저장/전송하지 않는다.
- 실제 유료 보고서 작성기의 프롬프트·본문에 이 숫자를 연동하거나 상업적 판매를 시작하지 않았다.
- 업로드, 운영 배포, 실제 AI/결제 호출 없으며 고객 검증도 아직 없다.
- 실사용 결과를 개선할 다음 단계는 **고객이 직접 체험하고, 어떤 질문/결과가 빠졌는지 피드백을 받는 것**이지 12장·35항목 유료 판매를 무작정 재개하는 것이 아니다.

**상태:** 실제 앱 1단계 입력화면에 비과금 계산 미리보기 연결 완료(개발 브랜치), 실제 사용자 반응·지불 의사 검증 전, 유료 보고서 판매 보류.
