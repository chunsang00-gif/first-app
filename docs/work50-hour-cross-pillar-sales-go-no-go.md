## 2. 기존 '출생시간의 독립 근거' 35건을 전체 원국과 대조

종전 `report-paid-core-hour-extension.js`는 출생시간 지지의 한 숨은 글자(지장간)에서 고객 질문 분야와 맞는 십성을 골라 **무료 화면에 노출된 월간/월지 본기/연간/시간의 네 분류와 다를 때** 첫 장 기술 후보로 취급했다. 하지만 그것은 **전체 원국의 네 기둥에 없는 새 전통 분류**라는 뜻이 아니다.

이번에는 `report-paid-core-hour-cross-pillar-audit.js`를 추가해 **출생년·월·일의 모든 실제 숨은 글자와 겉글자**를 확인했다. 무료 화면에 없다는 이유만으로 새로운 사주 분류라고 세지 않는다.

| 합성 입력과 질문 96건의 결과 | 건수 |
| --- | ---: |
| 전체 질문별 합성 테스트 | 96 |
| 기존 출생시간 기반 유료 첫 장 기술 후보 | 35 |
| **선택한 시간 속글자가 다른 출생 기둥에도 정확히 존재** | **26** |
| 나머지 출생 기둥에서 같은 글자 미발견 | 9 |
| 실제 별도 유료 원고의 판매 가치/고전 해석 우선순위 입증 | **0** |

여기서 35건은 **기존 무료 표시 분류 대비 새로운 위치/뜻의 기술 후보**일 뿐 유료 원고 합격 수가 아니다. 26건의 동일 분류도 위치별 의미가 같다는 뜻은 아니지만, **위치별로 왜 유료 심화 풀이가 성립하는지** 전문적인 해석 근거는 현재 준비되지 않았다. 나머지 9건은 글자가 중복되지 않았다는 뜻이지 해석 우선순위나 상품성이 증명됐다는 뜻이 아니다. 이 96건은 합성 표본이며 고객 대상 통계나 모델의 실제 생성 결과를 대표하지 않는다.

### 기존 고정 유료 시범 사례의 결정적 중복

`qa-current-core-preflight.CHART`: `壬戌 / 癸丑 / 乙未 / 癸未` (연 / 월 / 일 / 시).

고정 시범 고객 질문: “기존 일을 유지할지 새로운 기술을 배울지 고민 중입니다.”

`natal.hour.hidden.丁`(식신)을 출생시간에서 새로 찾은 '독립' 해석으로 제안했으나, **똑같은 丁**이 `natal.day.hidden.丁`(일지 未)와 `natal.year.hidden.丁`(연지 戌)에도 들어 있다. 따라서 *무료 화면이 이미 설명한 네 가지 대표 분류*에는 나오지 않아도 **원국 전체의 유일한 출생시간 분류는 아니다**.

이 차이를 정교한 명리법으로 해석해 실제 고객이 돈을 낼 가치가 입증된 적은 없다. 단지 숫자·문장 수를 늘리거나 새 모델을 쓰는 것으로 문제가 해소되지 않는다.
