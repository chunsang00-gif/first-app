# 작업55 — 실제 1단계 선택 비교의 모바일 읽기 흐름·입력 오류 접근성 개선

작성: 2026-11-22 (KST). 개발 브랜치: `fix-paid-qa-fact-bindings-20261014`.

## 무엇을 고쳤나

작업54에서는 실제 고객의 두 선택과 학습 부족시간·교육비 부족분을 볼 수 있었지만, 한 번의 입력에 **계산 내역 5행 + 비교 카드 2개 + 조정 방법 + 긴 체크리스트**가 동시에 나타나서 스마트폰에서는 많은 스크롤이 필요했다. 게다가 전체 보고서 상자를 `role="status" aria-live="polite" aria-atomic="true"`로 지정한 상태여서, 숫자를 한 자리 고칠 때마다 **화면읽기 프로그램이 긴 내용 전체를 다시 읽을 위험**이 있었다.

이번 변경은 내용을 삭제하지 않고 **중요도에 따라 접고 펼치는 구조**로 바꿨다.

1. **맨 위 핵심 상태와 숫자만 공개**: 입력한 실제 부족 학습시간, 교육비 부족분을 2칸(좁은 모바일 1칸)으로 보여준다. 시간이 부족하면 **주당 추가 몇 시간 / 기간 연장 몇 주**, 돈이 부족하면 **추가 교육비 얼마**가 바로 보인다.
2. **접힌 상세 보고서**: 기존 시간 계산 세부 내역, 현재 일 유지·새 기술 학습의 **두 선택 비교 카드**, 실제 확인할 사항은 브라우저의 기본 `<details><summary>…</summary></details>`로 접어 둔다. 키보드·터치로 펼칠 수 있고, 숫자를 고치는 동안 펼쳐 둔 상태를 가능한 한 유지한다.
3. **빈 입력 탐색 버튼**: 다섯 수치 중 일부만 입력했다면 빈 항목을 **0으로 취급하지 않으며**, 몇 개 비었는지와 **첫 번째 미입력 항목으로 바로 이동하는 버튼(`type=button`)**을 제공한다. 사주 입력 마법사의 `다음` 버튼이나 보고서 요청을 실행하지 않는다.
4. **입력 오류를 명확히 표시**: 음수, 문자 입력, 주당 169시간처럼 제한을 넘긴 수치가 들어오면 그 입력칸에 `aria-invalid=true`, 짧은 범위 안내와 `aria-describedby`를 설정한다. 정정하면 오류 상태를 지운다.
5. **화면읽기 길이 제어**: 별도 짧은 `role=status` 상자에 부족 학습시간·교육비·입력 대기 개수 또는 숫자 오류만 갱신한다. 상세 보고서는 `role=region`, `aria-live=off`로 읽는 사람이 필요할 때 탐색한다. 고객의 긴 고민 텍스트를 반복 낭독하지 않는다.
6. **주제 변경 시 개인정보·결과 삭제**: 현재 일↔새 기술 고민을 다른 질문으로 바꾸면 앞에서 입력한 업무명·기술명·학습시간·비용과 읽기용 상태를 지운다. 다른 고민을 입력한 뒤 옛 결과가 남지 않는다.
