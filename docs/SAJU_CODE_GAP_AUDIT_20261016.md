# 기존 코드와 명리 해석 기준 사이의 차이 — 2026-10-16

## 판정
**현재 기술 검증 성공 ≠ 전문 명리 해석 가능**. 핵심 계산값 상당수는 이미 존재하지만, **유료 첫 장의 두 번째 해석에 배정한 근거가 편향**되어 있다. 3차 유료 원문에서 기술 용어는 줄었어도 설명이 빈약하고 '마음의 두 중심' 등 계산하지 않은 심리 상태로 확장된 현상이 재현되었다. 다른 말투를 강제하는 검증 강화만으로 해결할 수 없다.

## 실 코드 확인 사항

| 코드 | 실제 상태 | 필요한 수정 원칙 |
| --- | --- | --- |
| `report-facts-node.js` | `facts.tenGods`(각 기둥과 숨은 글자의 십성), `facts.structuralEvidence.monthCommand`, `visibleStems`, `seasonalEvidence`, `natalClashes`, `rootConditions` 등이 이미 구성된다. | 새로운 사주 결과를 모델이 계산하게 하지 말고 **기존 계산 사실**과 출처 ID를 조합한다. 한계를 넘어서는 격국·용신 자동 확정은 금지. |
| `report-analysis-guidance.js` | `saju_core.temperament` 기본 근거는 월령 관련 자료, `saju_core.strength` 기본 근거는 **`facts.structuralEvidence.dayMasterRoots`**. 두 번째 항목은 `stem-linkage`, `root-condition` 강제 인용. | '기질을 뒷받침할 조건'의 판단에서 **십성·월령·출현 위치 등 다른 관련 근거의 역할을 먼저 정리**한다. 뿌리·충은 필요할 때만 보조로 넣고 강약·성격 점수를 발명하지 않는다. |
| `report-chart-contrast.js` | `TOPIC_POINTS.strength`에 `actual-day-master-roots`, `root-relation-overlap`만 배정. 읽기 쉬운 질문과 내부 `sourceAudit`은 최근 분리했지만 **해석용 핵심 원천은 여전히 두 항목뿐**이다. | 문구/금지어 패치 이전에 **근거 배정과 추론 순서를 재설계**한다. 십성 자료를 무작정 끼워 넣지 말고 정당한 질문-출처 대응표를 만든다. |
| `report-generation-request.js` | 본문에서 두 문단을 계절·겉글자 vs 뿌리·충으로 나누는 전송 지침, 정밀한 인용·금지 추론 지침 유지. | 바뀐 근거 모델과 정확히 일치하게 전송하되 기존 출처 보존·사전 감사 기능 유지. |
| `report-grounding-review.js` | 허위 충·기술 용어 과다·면책 반복 등 차단. | 반례 회귀 검증 유지. 그러나 **문장이 그럴듯해도 실제 근거가 심리 속성을 뒷받침하는지는 별도 의미 검증**이 필요. |
| `report-instruction-audit.js` | 유료 API 전에 전송한 `evidenceFocus`를 원본 계산과 대조하는 기능 있음. | 근거 재배정 뒤 **자기참조 검사가 되지 않도록**, 새로운 기본 원칙으로 템플릿과 반례 검사를 분리한다. |
| `report-facts-node.js` `profileBalance` | 단순 오행 개수와 MBTI 문자에 정해진 가중치를 더해 화면 참고 점수를 만든다(실제 성격 측정이 아니라는 경고 존재). | 별도 과제: 개인 능력·심리 측정 점수로 오인되지 않도록 UI와 상품 표현 재검토. 이번 첫 장 근본 해석과 혼동하지 않는다. |

## 우선순위

1. **명리 해석 설계**: 계산 사실 → 월령·일간·십성·다른 글자 관계 → 출처 간 맥락과 상징 → 고객 질문. `strength`가 뿌리·충 수업이 되지 않게 전용 연결표 마련.
2. **하나의 재현 가능한 사례부터 수작업 명리 풀이 감수**: 입력 원본·간지·실제 십성·계절·상호작용·해석 선택 방식(관법) 및 쓰지 못하는 주장 목록을 서로 대조. 과장 없는 독자용 두 문단 별도로 검토.
3. **다른 사례로 반증**: 같은 십성 다른 계절, 같은 계절 다른 십성, 출생시간 미상, 충이 없는 원국, 절입 경계. 특정 테스트 사례를 일반 규칙에 하드코딩 금지.
4. **코드 수정 및 무료 회귀 검사**: 기존 분리 원칙·유료 1회 실행 제한·과금 이후 원본 보관 보존. 새로운 원고 품질은 사람이 읽고 평가.
5. **유료 API는 그 뒤 별도 승인 시 첫 장 1회만**. 성급한 재생성과 12장 일괄 호출 금지.

## 핵심 원인 한 문장
**명리학적 결론을 만드는 규칙·근거 배정이 부족하니 모델이 뿌리·충을 늘어놓거나 아무 심리 서술로 빈 곳을 채우고 있었다.** 이것은 단순한 한국어 교정 문제가 아니다.
