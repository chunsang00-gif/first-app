# 작업52 — '형·충 우선순위' 고전 확인, 상품 설계 전환, 실제 계산형 워크북 1종 구현

작성: 2026-11-22 (KST). **연구 브랜치만 변경. 결제/유료 AI/운영 배포 승인 없음.**

## 1. 출생시간에 따라 차이가 난다는 것과 '고객 선택을 판정'한다는 것은 별개

작업51의 두 합성 사례(동일 음력 1982-11-24·동일 고민·오전 02:20 vs 오후 14:20)는 관계표상 출생일–출생시간 충과 출생월–출생시간 충의 끝점이 각각 다르다. 그러나 두 명식 모두 **월지 丑–일지 未 충이 이미 존재**하며, 연지 戌과 시간 지지 사이의 형/파 같은 **다른 관계도 공존**한다.

고전 `자평진전`의 〈논형충회합해법〉에는 다른 **합/회가 충·형을 풀거나 되레 충·형을 남기고, 다른 충·형이 월령 관련 관계를 견제할 수 있다**는 구체적인 예시가 있다. 바로 옆 〈논용신〉에서는 월령을 중심으로 전체 명식을 비교하는 전통적 논리도 제시한다. 그렇다고 이 특정 두 명식의 `월–시 충`과 `일–시 충` 중 하나를 **실제 직장 유지/학습의 우선순위**로 바꾸는 단일 판정법이 확보된 것은 아니다.

- **원문 근거:** [자평진전 원문 〈논형충회합해법〉/〈논용신〉](https://libokang.com/zh-hant/classics/bazi/%E5%AD%90%E5%B9%B3%E7%9C%9F%E8%A9%AE%E5%8E%9F%E6%96%87/) (제7·8편)
- **학술적 유보 근거:** 김만태(2013), [십이지 상호작용으로서 충·형의 근원 고찰](https://www.kci.go.kr/kciportal/landing/article.kci?arti_id=ART001802048), 한국학 36(3), 134–164. 특히 辰·戌·丑·未에서 충과 지장간의 작동 방식에 **정설이 없다는 점**을 설명한다.

**명리학 해석 결론: NO-GO.** 현재 확인한 관계표·고전 인용만으로 **상담 자격을 갖춘 검증된 판단 방법**이나 **고객의 실제 미래**를 제시하는 유료 기능을 출시해서는 안 된다. 월령의 우선성을 인용한 것만으로 이 특정 두 사례의 모든 합충형 작용을 자동 해소·우선순위화할 수 없다.

## 2. 무료 내용을 다른 말로 늘리지 않는 실제 기능을 만들었다

새 `report-work-skill-decision-workbook.js`는 기존 `report-buyer-work-skill-scope.js`의 **현재 일 유지 vs 새 기술 학습** 고민 판정과 `report-buyer-decision-context.js`의 기존 **고객 직접 입력 텍스트 검증**을 재사용한다.

다음은 **고객이 직접 입력하는 선택적 계산 필드**다. 이 정보는 사주·MBTI에서 나올 수 없다.

| 입력 필드 | 의미 | 출처 |
| --- | --- | --- |
| `weeklyStudyHours` | 매주 실제 확보할 수 있는 학습시간 | 고객 직접 입력 |
| `requiredStudyHours` | 기술을 익히는 데 필요하다고 고객이 예상한 총시간 | 고객 직접 입력·추정 |
| `targetWeeks` | 목표까지 남은 주수 | 고객 직접 입력 |
| `trainingCostKRW` | 고객이 예상한 교육비 | 고객 직접 입력·추정 |
| `availableBudgetKRW` | 고객이 교육에 쓸 수 있는 예산 | 고객 직접 입력 |

현재 기존 입력 폼에 **이 5개 입력을 강제하거나 결제 버튼과 연결하지 않았다**. 직접 입력한 수치와 빠진 정보만 계산하는 **비과금 실행 가능한 첫 상품 구조**를 분리 구현했다.

## 3. 같은 고민이어도 현실 조건에 따라 달라지는 계산 결과

동일한 가상 고객 입력: 현재 일 `물류 재고 확인`, 배울 기술 `엑셀 자동화`, 고민 `기존 일을 유지할지 새로운 기술을 배울지`. 숫자 모두 **합성 예시**다.

| 계산 결과 | A: 일정·예산 충분한 경우 | B: 시간·예산 부족한 경우 |
| --- | ---: | ---: |
| 일주일에 확보할 학습시간 | 8시간 | 3시간 |
| 필요한 총 학습시간 | 60시간 | 60시간 |
| 목표 기간 | 8주 | 8주 |
| 기간 내 학습 가능한 시간 | **64시간** | **24시간** |
| 현재 속도에서 필요 주수(소수점 올림) | **8주** | **20주** |
| 목표 기간 내 부족 시간 | **0시간** | **36시간** |
| 예상 교육비 | 150,000원 | 300,000원 |
| 가용 교육 예산 | 200,000원 | 100,000원 |
| 추가로 필요한 교육비 | **0원** | **200,000원** |

이것은 실제 문제 해결에 연결할 수 있는 **추가 의사결정 정보**다. 다만 두 가지 주의가 필요하다.

1. **사주로 계산한 고객 성향이나 학습 성공 확률이 아니다.** 고객이 입력한 시간·교육비의 사칙연산일 뿐이다. 학습 이수 가능성을 보장하지 않고, 직장을 유지하면서 기술을 배울 수도 있다.
2. **'돈을 낼 가치'는 아직 입증하지 않았다.** 누구나 수행할 수 있는 시간·예산 비교 기능만으로 사주×MBTI 유료 보고서가 차별화된다고 볼 수 없다. 실제 사용자의 만족·지불 의사/반복 활용을 확인해야 한다.

## 4. 실제 실패/입력 누락까지 처리

`qa-work-skill-decision-workbook-tests.js`에서 다음을 반드시 확인한다.

- 시간·예산이 모두 맞는 경우와 둘 다 부족한 경우를 **실제 다른 수치**로 계산
- 예산 0원과 공란을 구분, 빠진 정보가 있으면 **계산 불가라고 그대로 표시**
- 주당 학습 가능 0시간이면 완료 예상 주수를 **0이나 무한대가 아닌 미확정(null)**으로 반환
- 목표시간이 정확히 가능한 경우 경계값 검증
- 잘못된 숫자, 임의 키, 개인 연락처·HTML 삽입 등의 입력 거절
- 외부 AI·결제 요청 없음; 과금·판매 승인을 발생시키지 않음
- **동일한 출생정보라도 실제 학습 가능시간·예산이 달라지면 출력이 달라짐**. 한편 어떤 생일이더라도 계산 공식 자체는 동일해야 한다.

## 5. 제품 방향을 변경하는 데 필요한 현실적인 판정

현재 12장·35항목을 전부 유료로 보장하는 모델을 강행하면 빈 문단·반복 문장·가상의 개인별 예언이 발생할 위험이 크다. 다음은 12장 확대가 아니라 **현실 데이터가 있는 한 가지 결정용 '가변형 워크북'**을 상품 구조의 핵심 후보로 놓는 것이 더 낫다.

- **사주**: 계산할 수 있는 전통적 위치·관계를 **근거와 불확실성**까지 표시. 유리한 직업이나 확정된 미래를 판정하는 수단이 아니다.
- **MBTI**: 고객의 자기보고 결과를 **대화·성찰의 출발점**으로만 사용. 실제 능력·학습 속도를 추정하지 않는다.
- **고객의 현실 선택**: 직접 입력한 시간·비용·기한·실제 대안에 따라 부족조건, 확인 질문, 변경 가능한 계획을 자동 계산. 사실로 확인되지 않은 입력은 공란으로 남긴다.
- **유료 모델**: **가변형**, 실제 독자 가치가 확인된 분야만 확대하며, 첫 장 285자처럼 무료 풀이를 재포장한 원고를 팔지 않는다.

**상태:** 계산형 워크북 첫 기능은 코드로 구현했지만, 아직 기존 실제 앱 UI/유료 보고서 작성기/결제 흐름에 연결하지 않았다. **이 기능의 실제 사용성 검증 및 독자가 지불할 가치의 실증 0건**이다. 다음 과제는 **구매 기능을 건드리지 않은 상태에서 입력 화면과 결과 미리보기로 고객이 직접 써볼 수 있게 연결**하고 그 경험을 검증하는 것이다. 고전/원국 후보를 더 많이 세는 테스트는 추가하지 않는다.
